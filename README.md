# Санкции США и ЕС и динамика рубля

Исследовательский проект с 01.01.2014. Python → PostgreSQL → DataLens.

## Статус первой версии

Реализованы загрузка USD/EUR/CNY из ЦБ, архив исходных ответов с SHA-256, локальный кеш SQLite, публикация в PostgreSQL, CSV для DataLens, расчёт изменений через 1/5/20 наблюдений, журнал запусков и ежедневный цикл.

**Календарь пока содержит только 4 проверенных примера, а не полный перечень санкций.** На нём нельзя делать выводы о санкциях в целом. Автоматическое обнаружение новых санкций, полный исторический календарь, ставка/нефть/доллар, регрессии и интервалы неопределённости — следующие этапы, пока не реализованы. DataLens-дашборд нужно подключить и настроить; файлы проекта сами не создают облачный аккаунт.

## Запуск в Windows

Проверено 22.10.2026: PostgreSQL и загрузчик работают в Docker. В PostgreSQL опубликованы 9480 строк, по 3160 на USD/EUR/CNY, до 22.10.2026, а также 4 события и 36 реакций. Повторная загрузка последних 40 дней не увеличила число строк. 6 автоматических тестов прошли. Учётная запись `datalens_reader` проверена: чтение работает, право INSERT отсутствует.

1. Открыть Docker Desktop и дождаться работающего Linux engine.
2. Открыть PowerShell в этой папке и выполнить `./setup.ps1`.
3. Смотреть загрузку: `docker compose logs -f pipeline`.
4. Проверить `exports/quality.json`: дата обновления, число строк, последние даты по валютам.

Первая загрузка: годовые интервалы с 2014 года. Следующие: повторная проверка последних 40 дней и догрузка пропущенного периода. Исправления более старой истории требуют отдельной полной перезагрузки. Цикл — каждые 24 часа после завершения предыдущей попытки; работает только при запущенном Docker и бодрствующем компьютере. После сна/перезапуска история догружается. Данные PostgreSQL сохраняются в Docker volume. `docker compose down` останавливает сервисы; не добавляйте `-v`, если хотите сохранить базу.

Без Docker: `python pipeline.py`. Используется стандартная библиотека Python 3.11, SQLite и CSV. Для пересчёта без сети: `python pipeline.py --offline`.

Тесты: `python -m unittest -v`.

Перед выключением компьютера можно выполнить `./stop.ps1`: он корректно остановит только сервисы этого проекта, сохранив базы и рабочие книги. После аварийного выключения PostgreSQL может несколько минут восстанавливать файлы. Загрузчик после временной ошибки повторяет попытку через 60 секунд; после успеха — через 24 часа.

## Подключение DataLens

База `research`, пользователь только для чтения `datalens_reader`, пароль `READER_PASSWORD` из локального `.env`. Пароли создаются скриптом, не публикуются в Git и не копируются в Docker image.

С Windows: сервер `localhost`, порт `55432`. Для подготовленного локального DataLens используется общая Docker network: хост `db`, порт `5432`. База `research`, схема `public`, пользователь `datalens_reader`. SSL внутри этой локальной Docker network выключен. Порт базы привязан только к loopback, не к публичному интерфейсу.

Облачный Yandex DataLens не может подключиться к `localhost` ноутбука. Для него нужен доступный сервер PostgreSQL с TLS и ограничением доступа либо ручная загрузка CSV первой версии.

Локальная открытая версия DataLens: https://github.com/datalens-tech/datalens . Официальный репозиторий сохранён в `vendor/datalens`; его `init.sh` создал уникальные секреты и production-конфигурацию. Отдельный проект запускается командой `./start-datalens.ps1`. Интерфейс привязан к `http://localhost:8080`, только на этом компьютере. Логин `admin`, пароль — `AUTH_ADMIN_PASSWORD` в `vendor/datalens/.env`. Секреты и локальные vendor-файлы не включаются в образ загрузчика и Git. Не публикуйте `.env`, production-конфигурацию и init-local.log.

Удобная памятка для входа сохранена в `data/ACCESS.txt` (содержит пароли, не публиковать). Её можно заново создать командой `./write-access.ps1`. Проверка состояния всего проекта: `./check.ps1`. Версия исходников DataLens: `1cebb39b37e3ccd879f43ba17d96d98fb90c85ab` (release 2.9.0). Календарь `events.csv` подключён к загрузчику отдельным файлом: изменения будут прочитаны при следующем запуске загрузки без пересборки образа.

Таблицы: `fx_rates`, `sanctions_events`, `event_reactions`. Готовая витрина: `dashboard_events`.

## Первые графики

1. Линия: `effective_date` по X, `rub_per_unit` по Y; фильтр `currency` (не суммировать разные валюты).
2. Таблица событий: `announcement_date`, `title`, `jurisdiction`, `source_url`.
3. Столбцы реакции: `title` по X, `change_pct` по Y; фильтры валюты и горизонта. Положительное значение означает ослабление рубля.
4. Контроль: таблица `other_events_in_window`, `methodology_break`. До расширения календаря число пересечений — нижняя оценка.

## Методология и ограничения

Курс ЦБ — официальный курс за единицу валюты (Value / Nominal), не цена доступной сделки. Дата в XML — дата действия курса, не время рыночного наблюдения. База реакции — последняя дата действия не позже даты объявления; конец — 1/5/20 следующих опубликованных наблюдений. Это явная приблизительная привязка, а не точная оценка внутридневной реакции. Повторяющиеся значения не удаляются: равный курс не означает отсутствие новой публикации. Выходные календарно не добавляются.

После 13.06.2024 методика USD/EUR меняется; для дат действия граница отмечена 14.06.2024. Пересекающие её окна помечены. Будущие незавершённые окна исключаются. События без `source_verified` не используются в расчётах. Время объявления пока отсутствует, даты вступления в силу остаются пустыми, если не проверены.

Не считать положительную реакцию доказательством влияния санкций. Нужны полный календарь по заранее заданным правилам, учёт ожидаемости, пересекающихся событий, нефти, ставки, валютных ограничений и разных рыночных режимов. Нельзя отбирать события по уже увиденному движению рубля. Четыре стартовые записи служат проверкой пайплайна.
